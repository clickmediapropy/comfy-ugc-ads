# Failure classes: why H3 clips go wrong and what the skill does about each

The skill prevents classes of defects, not single bad clips. Every defect found in a review becomes a row here: the class, its root
cause with evidence, the prevention (script rule, still rule, prompt compiler, lint rule) and the check that detects it. A fix to one
clip without a row here is not done.

## The root cause behind most rows
MiniMax H3 is trained on video captions written in MiniMax's own rewrite format, and Comfy samples it without a negative prompt
(`BasicGuider`, cfg 1). It does not follow instructions. It reads every word as something seen or heard in the clip:
- "he stops talking", "no words", "no speech" put talking into a silent clip.
- "nothing floats" came back as a floating glass. "never extra words" came back as extra words.
- "picks up the glass, sips, puts it back" gives the motion as a summary, so H3 invents the grip and gets it wrong.

So `scripts/h3prompt.py` writes only what is seen and heard, in the official format (FL2VA for keyframed takes, full-reference for
packshot/voice takes), and its `lint()` blocks the spec patterns behind the rows below before anything is paid for.
Sources: `huggingface.co/MiniMaxAI/MiniMax-H3` docs `VIDEO_PROMPT_WRITING_GUIDE_base_en.md` and `..._ref_en.md`, README (output 4-15 s);
ComfyUI `comfy_extras/nodes_minimax_h3.py`; Comfy's H3 prompting guide (turbo = "slightly weaker audio and motion", ~25 steps = better motion).

## Classes

| Speech in a silent clip (babble, lips moving) | 2026-09-30 drink and yawn inserts: "Thank you, Non-Binary IT Guy" | The old template described a talking creator in every take ("talking straight into the phone", "speaks English", "stops talking"). The official format only has speech where a speaker `(S1)` and `<d>…</d>` appear | Take `kind: action`: no speaker ID, no speech words, no voice reference, lips described physically. Lint `SPEECH_IN_ACTION` | `review.py`: an action take expects NONE, so any word is EXTRA blocking |
| Extra words after the last line | 2026-09-30 line 4: "You guys are going to" | 1.5 s of idle time after the line in a talking take; negations ("never extra words") | `seconds: "auto"` sizes the take to its beats; the final beat is a concrete visible state. ## Adding a class
1. Name the class, not the clip ("prop floats", not "the glass in take 3").
2. Find the cause with evidence: the exact prompt that was sent (`$W/graphs/<label>.api.json`, node `1`), the official guide, the settings.
3. Add the prevention where it belongs: script rule (`SKILL.md` step 3), still rule (step 4), compiler (`h3prompt.compile`) or lint rule (`h3prompt.lint`).
4. Add a detection check to `review.py` if it can be automated.
5. Prove it: run `take_graph.py --lint` on the spec that produced the defect (it must fail), then render once with the fixed spec.
